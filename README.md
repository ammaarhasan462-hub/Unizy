# Unizy

Study website for UK university students: pick your uni, degree and modules, then get notes, flashcards, topic tests, essay marking and an AI tutor built around your course.

## Layout
- `site/`: the website (static files, served by Cloudflare Pages). Build output directory: `site`. No build command.
- `supabase/functions/ai/`: the AI function (Supabase Edge Function) that calls Claude within daily limits.
- `supabase/functions/import-timetable/`: 1-click setup. Reads an uploaded timetable or module handbook (PDF or screenshots) and returns modules, weekly classes, one-off sessions, deadlines/exams and handbook summaries, matched to the uni's module list. Counts as one AI action.
- `supabase/functions/calendar-sync/`: reads a student's uni calendar feed (Moodle, Canvas, Blackboard, timetable iCal/webcal link) server-side and returns its events for the Plan. `ics.ts` is the iCal parser.
- `supabase/functions/verify-uni/`: emails a 6-digit code to a student's uni address (e.g. @ucl.ac.uk) and confirms it. Needs the `RESEND_API_KEY` secret.
- `supabase/sql/campus.sql`: tables and RPCs for uni verification, module hubs, the campus marketplace (plus the public `market` storage bucket for photos) and Study Mode focus rooms.
- `site/assets/campus.js`: the website side of 1-click setup, calendar sync, verification, module hubs, marketplace and Study Mode (shown under Campus and Plan in the app).

## Hosting
- Cloudflare Pages project connected to this repo; every push to `main` redeploys.
- Supabase project `unizy` (London) for accounts, saved work and the AI function. The Anthropic key is stored as the `ANTHROPIC_API_KEY` function secret.

## Home page try box and traffic sources (Nov 2026)
- Home page promise: "Any lecture. Exam-ready in a minute." The try box (`site/assets/try.js`) has two tabs. **Paste your notes**: signed-out visitors get 8 flashcards and 3 practice questions from their own notes via the edge function `supabase/functions/try-cards` (deploy with verify_jwt off; cheap model; 3 goes a day per browser and 60 per network (campus wifi shares IPs), 300 site-wide, inside the daily £ budget; counters in `try_runs`, network = daily-salted hash, no IPs). **Find your module**: real cards and questions from the fact-checked module packs listed in `site/data/try-index.json` (rebuild with `python3 tools/build_try_index.py` after changing packs).
- Cards made in the try box are kept in localStorage `unizy-pending`; the app's Flashcards view offers "Add them" to the open module (saved as the student's own cards).
- Short links for bios, posts and posters (`site/_redirects`): /tiktok /tt /ig /insta /snap /wa /yt /li /reddit /qr /poster /soc /friend → `/?ref=<source>`. The home page counts `src_<source>` (also from the referrer or in-app browser) and the sign-up page counts `join_<source>`; both are anonymous daily totals in `site_events`. `?notrack=1` on any page stops counting on that device (for the owner's own devices).
- Link preview image: `site/assets/og.png` (1200×630).

## The marker (Nov 2026)
- Focus: exam practice and marking for UCL students. Home page (`site/index.html`) and marker (`site/mark.html`, served at `/mark` and `/modules/<CODE>`) are generated by `python3 tools/build_marker_pages.py`; the brand name is the `BRAND` constant there.
- `site/assets/mark.js`: module search over all 6,682 UCL catalogue modules, practice questions, timed answers, results, history and "tell us your real mark".
- `supabase/functions/marker/`: writes 8 exam-style practice questions per module on first open (cached for everyone, uses the daily £ budget only) and marks answers against UCL grade bands + department rubrics (counts as an Assess marking). Deploy with verify_jwt off (it checks the user itself).
- Tables in `supabase/sql/marker.sql`. Department rubrics live in `marking_rubrics` (one UCL-wide default plus departments that publish criteria). Real First-class model answers go in `model_answers` (set `published` once checked).
- Play, Campus, Plan and friend groups are hidden from the app navigation (code kept).
- Free trial (Nov 2026): 3 days from sign-up, with 3 markings and 3 tutor questions a day (UK days); after that nothing free (marking and the tutor need Pro; notes, flashcards and tests stay free). Numbers live in `ai_settings` (`trial_days`, `trial_daily_assess`, `trial_daily_actions`; `free_weekly_*` = 0 means no free plan after the trial). The limit messages students see come from `ai_take_plan`'s `message` field, so copy changes don't need the functions redeployed. SQL: `supabase/sql/trial_3day.sql`.
- Attachments (Nov 2026): in the dashboard, Practice & marking answers and Tutor questions can include files, photos and videos (`site/assets/attach.js`). Limits: 10 photos, 2 videos, 5 files (PDF, .docx, .txt/.md); only shown if exceeded. The browser resizes photos to JPEG (1568px), turns each video into 3–8 still frames (no sound), and extracts text from .docx. The server checks the same limits in `supabase/functions/{marker,ai}/attach.ts` (keep the two copies identical). The marker accepts an answer that is only photos/attachments and saves a typed transcript in `mark_attempts.answer`; tutor attachments count as tutor actions (1 unit per 5 images, 1 per PDF), not as Assess markings. Attachments live in memory while the dashboard is open (kept across tabs, removed with ×; not kept after a reload).

## Study area (Nov 2026)
- **Module Map** (`site/assets/mark.js`, module page): each module is split into 6–10 topics (`module_topics`). Every topic has 2 Foundation quick-recall questions (self-checked, with a short answer; "Not yet" adds a flashcard), 1 Exam-style and 1 First-class stretch question (`module_questions.tier`, `topic_pos`; `steps` holds a worked solution revealed one step at a time for quantitative questions). Students rate each topic red/amber/green (`topic_ratings`) and see a mastery % worked out in `site/assets/study.js`.
- Questions are written by the `marker` function the first time a signed-in student opens a module (one call, about 4p, inside the daily £ budget, max 15 new modules per student per day; `question_jobs` stops two students triggering it twice). The page polls until the topics appear.
- Background batch: `POST marker {action:"warm", code}` with header `x-warm-key: $WARM_KEY` writes a module with no user. Its spend goes to `ai_batch_spend`, not `ai_spend`, so it never uses up students' daily budget.
- **Marking** now also returns `lost` (exact quotes from the answer with why/fix, highlighted in the "Where you lost marks" tab), `model_plan`, `model_paragraph` (replaces the full example answer), `rewrite` (the paragraph to rewrite first) and 2–4 flashcards saved to `review_cards`. Resubmitting a rewrite sends `prev_id`, and the result shows the change in mark.
- **Today** (dashboard home, `site/assets/dashboard.js`): exam countdowns (`my_modules.exam_date`, set on the module page), the next question to do (nearest exam → weakest topic → recall first if under 25%), flashcards due (light SM-2 in `study.js`), and mastery per module.
- Tables and RPCs: `supabase/sql/study.sql`.

## Dashboard workspace (Nov 2026)
- **Top bar** (`dashboard.js`): command palette (Ctrl/⌘ K or `/`) over your modules, their topics, pages and the catalogue; `CODE W3` / `CODE T3` jumps to topic 3. Flashcards-due badge, plan chip, and a global R/A/G filter (Weak / Medium / Mastered) that highlights matching topics in the sidebar and every Module Map (`html[data-rag]` + `[data-rs]`). A topic's status comes from `UnizyStudy.ragStatus`: practice mastery once started (<40 weak, <70 medium), else the student's own rating.
- **Sidebar**: University → Module → Topic tree with R/A/G dots and mastery %; Revision mode switch (Flashcards `/dashboard/cards`, Topic arena `/dashboard/practice`, Exam simulator `/dashboard/exam`). Module links open in the current mode.
- **Flashcards**: a deck per module (`review_cards`), review with keys (Space, 1/2/3), browse and delete.
- **Exam simulator**: random unanswered exam-style or First-class question, strict countdown (`?exam=MIN` on the answer view), no steps / mark scheme / warnings until marked.
- **Module page** (`mark.js`): Study mode / Parse mode. Parse mode sends slides, transcripts or notes to the `ai` function (`kind: notes`, `json: true`, counts as tutor actions) and gets study units with flashcards; units are kept in localStorage `unizy:units:CODE` and cards can be added to the deck. Sticky tier pills: Pass (50%) = quick recall, Merit (60%) = exam-style, 1st Class (70%+) = stretch.
- **Answer view**: maths / Greek / code formatting toolbar; right-hand inspector with the band scale, the question's mark scheme, model answer (spoiler) and examiner warnings from earlier markings.
- **Result view**: annotated answer on the left; inspector on the right with the evaluation card, **Mark allocation** (`result.allocation`: line items worth 100, awarded/available), 1st Class model answer accordions and **Examiner warnings** (`result.warnings`). Both fields are written by the `marker` function from v11; older results fall back to criteria and lost-mark notes.
- **Dashboard tour** (`site/assets/tour.js`, `tour.css`): a one-time, step-by-step introduction (11 steps) the first time a student reaches Home after sign-up and set-up. Spotlights the real element on wide screens, centred cards with small interactive previews otherwise. Seen once per account (`user_metadata.tour_v1`, set via `PUT /auth/v1/user`) and per device (localStorage `unizy:tour1:<uid>`). Waits for the personal welcome screen to close. Replay: Account → "Replay the dashboard tour". Events: `tour_open`, `tour_step_<id>`, `tour_done`, `tour_skip_<id>`.
